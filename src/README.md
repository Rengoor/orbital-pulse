# Orbital Pulse

*An astronaut health tool that can never talk itself into reassuring you.*
Decision support, not diagnosis. NASA Space Apps Challenge 2026, Heilbronn: Create Health Monitoring Software for Astronauts on Space Missions. The judge-facing overview is the [repository README](../README.md); this file is the technical index.

Readings go through independent pipelines that cannot see each other; a small
deterministic Checker turns their proposals into one verdict; every decision is
hashed, signed and chained so Earth can verify and replay it later. Tiers:
GREEN, YELLOW, RED and GREY (data cannot be verified; treated as urgent).

## Which output depends on which dataset

Remove the data and that output must disappear; nothing falls back to a
substitute.

| Dataset | What it drives | Remove it and |
|---|---|---|
| OSDR Inspiration4 (OSD-569, OSD-575) | Personal glucose baselines for pipeline A; the blood-panel table in the Earth view; the simulator's one real reading (each crew member's post-flight glucose draw) | Pipeline A skips CUSUM for glucose (no guessed baseline); the blood-panel table is empty; the simulator sends simulated glucose labelled simulated |
| OSDR RadLab | Radiation context panels in the views (absorbed dose, display only; never fed to the decision pipelines, see `data/nasa/README.md`) | The context panels say the source is not loaded |
| CCMC DONKI | The space-weather event timeline (context only) | The timeline says the source is not loaded |
| None (simulated, labelled so) | Daily vitals from `data/sim/simulator.py` and the scenario files | — |

## Delay-aware autonomy

Near Earth, a flight surgeon can answer a medical verdict in about two minutes. At Mars,
the answer takes 8 to 47 minutes, often longer than the action can wait. For every verdict,
the backend logs a signed **handoff** saying whether Earth can answer before the action has
to start (`GROUND_IN_LOOP`) or whether the crew must act on the onboard verdict alone
(`ONBOARD_AUTHORITY`). A handoff never changes a tier or an action.

The HUD tells the wearer which case they are in, and shows a ground review only once it has
had time to arrive. The Earth view counts the decisions the crew owned alone, and explains
each one. `evidence/results/autonomy.md` shows the shift. On the scenario days, the crew owns
0 of 3 alerts alone near the Moon, 1 of 3 at Mars closest approach and 3 of 3 at Mars's
farthest. Deadlines are project-defined placeholders (`backend/checker/autonomy.yaml`).

## Run

One command starts the backend and the crew simulator, and opens the helmet HUD, the crew health monitor and the Earth base in the browser (Ctrl+C stops everything):

```bash
backend/.venv/bin/python run_demo.py      # Windows: backend\.venv\Scripts\python run_demo.py
```

The individual commands:

macOS / Linux:

```
python -m venv backend/.venv
backend/.venv/bin/python -m pip install -r evidence/requirements.txt   # includes backend + data deps
export SIGNING_KEY=local-dev-signing-key        # the API refuses to start without one
backend/.venv/bin/python -m uvicorn backend.api.main:create_app --factory   # backend + UI on :8000
backend/.venv/bin/python -m data.sim.simulator --storm                      # live check-ins
backend/.venv/bin/python -m pytest backend/tests data/tests evidence/tests validation/tests -q
backend/.venv/bin/python -m evidence.run_all --seed 42                      # regenerate evidence/results/
```

Windows (PowerShell): same commands with `backend\.venv\Scripts\python` and
`$env:SIGNING_KEY = "local-dev-signing-key"`. The Makefile wraps the same
targets (`make api`, `make demo`, `make reproduce`, `make test`, `make redteam`, `make validate`) where GNU
make is available.

The UI is at http://127.0.0.1:8000/ui/. Records are in memory unless
`RECORDS_PATH` points at a SQLite file (which also makes the downlink queue
survive restarts).
