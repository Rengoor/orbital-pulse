# Contributing

Ground rules that keep the design honest. They apply to every change.

1. **`data/schemas/` is the contract.** Changes are additive only (new optional fields). Everything that crosses a boundary (reading, proposal, verdict, record, review, ack, handoff) is validated against it.
2. **Folders do not import each other's code**, with two exceptions: `backend/` reads `data/schemas/` and `data/` processed files, and `evidence/` and `validation/` import `backend/`. The frontend talks to the backend over HTTP only.
3. **Pipelines stay blind.** A pipeline never sees another pipeline's output. New pipelines are discovered by folder under `backend/pipelines/`; there is no registry file.
4. **The Checker is the only thing that decides**, and it is deterministic. Views display verdicts; they never compute one. No tier, threshold or medical rule may live in a frontend file.
5. **Never downgrade silently.** A tier can only be lowered through the confirmed-data-fault path in the Checker. GREY means "cannot verify", never "probably fine".
6. **Label every number.** Real NASA data carries its dataset; everything else is labelled simulated. No fallback ever substitutes fake data for a missing real source.
7. **Generated output is not committed**, except `evidence/results/`, `validation/results/` and `data/nasa/*/processed/` (small, regenerated by one command each).
8. **Report only what you ran.** Any number in a README or results table must come from a run of the committed code (`make reproduce`, `make validate`) or from CI.
9. **Tests gate merges.** `make test` and `make redteam` must pass; the red team must stay at zero unsafe approvals.
10. **Windows works without make.** Every Makefile target is one line you can run by hand; the README lists them.
